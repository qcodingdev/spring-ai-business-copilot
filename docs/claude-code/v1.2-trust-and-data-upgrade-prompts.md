# v1.2 可信执行底座与外部业务查询目标实施 Prompt

> 使用方式：按顺序执行。每个 Prompt 是独立可验收切片，前一切片未通过 CI 时不要进入下一切片。  
> 规划依据：`docs/v1.2-trusted-execution-plan.md`、`docs/current-project-audit-2026-07-16.md`、`docs/upgrade-roadmap.md`。  
> 总规则：不增加第六个模块，不拆微服务，不引入 Redis、消息队列、IAM 或工作流平台，不创建 tag/Release，不合并到 `main/master`。

## Prompt 1：建立 actor 与对象授权最小公共层

```text
目标：建立四个高风险模块真实复用的 actor/role/object policy 契约，但不建设 IAM。

建议分支：
- feature/v1.2.0-actor-context

范围：
- 新建 platform/common-security
- app 的 Spring Security 适配
- common-web 的请求上下文和安全错误契约
- 对应测试、模块文档和 ADR

必须实现：
1. CurrentActor(actorId, roles) 和 CurrentActorProvider。
2. BusinessRole 仅包含 ADMIN、OPERATOR、REVIEWER。
3. ObjectAction 与 ObjectAccessPolicy 的最小接口。
4. 高熵 token 生成、SHA-256 摘要和常量时间比较辅助。
5. app 从 Spring Security Authentication 构造 CurrentActor。
6. 明确授权矩阵：
   - ADMIN 可处理全部对象。
   - OPERATOR 只创建和处理自己的对象。
   - REVIEWER 只处理明确进入复核队列的对象。
7. 对象不可见或跨 owner 访问使用安全 404；合法对象的过期、重放和状态竞争使用稳定 409。

必须测试：
- 三角色 actor 读取。
- owner、跨 owner、管理员和 reviewer queue 决策。
- 匿名身份、角色缺失和非法 actor。
- token 摘要不等于明文，比较不回显 token。
- 请求结束后上下文清理。

约束：
- 不实现用户、组织、密码、OIDC、LDAP、多租户或 ACL 管理后台。
- common-security 不保存业务状态。
- app 负责安全框架适配，业务模块只依赖窄接口。

验收：
- 新模块测试通过。
- bundled app 认证行为不回退。
- 现有 401/403 保持兼容，新增 404/409 错误码稳定。
```

## Prompt 2：迁移四模块可信确认生命周期

```text
目标：封闭跨 actor、明文 token、重启丢失、重放和并发状态风险。

建议分支：
- feature/v1.2.0-trusted-confirmation

范围：
- Flyway V11
- Data candidate
- Support reply draft/ticket
- Report draft/export
- Resume criteria/assessment
- 各模块审计、清理任务和并发测试

必须实现：
1. 创建 data_sql_candidates 数据库表，Data 不再使用内存 Map。
2. Data candidate 保存 sql、token_digest、status、owner_actor_id、request_id、模型/Prompt 元数据和生命周期时间；不保存完整用户问题。
3. Support/Report/Resume 增加 owner、token digest、状态动作操作者以及必要 reviewer queue 字段。
4. V11 统一失效 v1.1 尚未消费的明文 token，不迁移为继续可用 token。
5. 明文 token 只在创建响应中返回一次；查询、日志、审计、错误和后续响应不回显。
6. 确认、执行、取消、导出、复核同时校验 actor、角色、对象、token、状态和有效期。
7. 所有状态变化使用数据库条件更新；Support draft 与 ticket 状态在同一事务中校验 expected-state。
8. Report 按 ID 导出增加对象授权。
9. Resume criteria 由 owner/admin 确认；assessment 只能由 admin 或明确分配 reviewer 标记 REVIEWED，禁止 OPERATOR 自审。
10. 增加过期清理/匿名化任务和最小审计事件。

必须测试：
- owner 成功，另一个 OPERATOR 即使持有正确 token 也失败。
- REVIEWER 只能处理明确队列对象。
- ADMIN 可处理全部对象。
- 错误 token、过期、重放。
- 20～50 个并发确认只有一个成功。
- confirm/cancel 竞争只有一个状态转换成功。
- 应用重启后 Data candidate 仍按状态和有效期工作。
- V10→V11 历史升级保留业务数据且旧 token 全部失效。

审计事务策略：
- 平台库确认、取消、复核状态和审计同事务，fail-closed。
- Data 外部 SQL 执行前必须先写执行意图，失败时不得执行 SQL。

约束：
- 各模块保留自己的状态表，不建立万能 confirmation/workflow 表。
- 不引入 Redis 或消息队列。

验收：
- 数据库不再新增明文 confirmation/review token。
- 审计同时记录 creatorActorId 和 actionActorId。
- 全量状态、并发、迁移和 API 契约测试通过。
```

```text

建议分支：
- feature/v1.2.2-postgresql-target

范围：
- modules/data-copilot
- app 查询 DataSource 装配
- ai-guardrails 方言上下文
- PostgreSQL Testcontainers

3. schema/table/column allowlist 按 PostgreSQL 规范化；未配置 column allowlist 时采用文档化的安全默认。
4. metadata、Prompt schema、生成后校验和执行前校验共享同一 dialect context。
5. 启动/诊断只返回连接状态、方言、只读状态、允许 schema/table 数量和权限缺口类别。
6. 诊断不得返回 JDBC URL、用户名、密码、SQL 或数据库原始异常。
7. 使用独立 PostgreSQL Testcontainer 和独立只读账号，不与平台库复用。

- 生成后与执行前使用同一 PostgreSQL 方言校验。
- Flyway、平台审计和其他 Copilot 从不使用 businessQueryDataSource。

约束：
- 不在线保存凭据。
- 不支持跨库 JOIN、存储过程或写操作。

验收：
- 独立 PostgreSQL 业务库契约全部通过。
- 平台库与查询库边界没有回退。
```

## v1.2 最终完成定义

- Data、Support、Report、Resume 的高风险对象绑定 owner、角色、状态、有效期和不可重放 token。
- 五个模块可以在不扫描项目根包的外部最小宿主中独立装配。
- 审计准确、最小化、可保留、可匿名化和可删除。
- PostgreSQL/MySQL 只读查询契约可重复验证。
- 客户端错误不泄露 SQL、provider 原文、内部类名或堆栈。
- 项目仍是单体、多模块、可运行的业务样板，不演变为通用平台。
