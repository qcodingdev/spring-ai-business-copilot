# 2.3.0 升级执行路线

1. 保留 2.2.1 全 Reactor 基线和版本证据。
2. 先定义页面/API/角色/状态/确认/i18n 设计，再迁移到 Vue。
3. 按 Data、Knowledge、Support、Report、HR 顺序接入主闭环和企业能力。
4. 后端统一传播显式 locale，并把低基数 locale 写入审计。
5. 所有 REST 企业连接统一接入 SSRF、超时、大小、分页、条目、JSON 与密钥边界。
6. 删除已无消费者的 Thymeleaf/原生 JS，保留 Spring SPA fallback。
7. 执行前端、Reactor、固定评测、数据库、Docker、运行模式、真实模型和 SBOM 门禁。
8. 更新中英文公开文档、模块文档和虚构数据截图，完成正式版本门禁后合入主干并发布
   `v2.3.0`。

## 企业闭环收口

正式版在 V29/V30 的国际化、外部连接安全和知识质量维度基础上增加 V31：

- Data 治理对象不可变版本、双人审批和单一激活版本；结果快照到 Report 的交接采用
  `READY → CLAIMED → CONSUMED` 条件状态，失败释放、并发不重复消费。
- Knowledge 来源同步按 ACL 失败关闭，质量队列保留证据、答案、补救动作和处置版本。
- Support 外部工单并发幂等导入，回写采用准备、确认、处理中、未知结果和带证据恢复，
  永不自动发送客户消息。
- Report 只允许可重复且可执行的调度来源，调度任务带租约、过期回收和运行记录；确认
  仍不代表外部发布。
- HR 候选人授权绑定用途，评估队列可原子领取复核；面试成员、多人意见和入职实例/
  任务形成持久状态，不评分、不排名、不自动筛退、不写 ATS。

浏览器控制按 `browser-control-deferred.md` 延期，不混入本版本。
