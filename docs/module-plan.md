# 模块详细规划

## 1. 模块设计原则

每个业务模块都必须满足：

- 业务场景明确。
- 输入输出清楚。
- 能独立 demo。
- 能复用平台能力。
- 有安全和审计边界。
- 有样例数据或样例文件。

模块不是功能堆叠，而是可交付的业务场景。

## 2. Data Copilot：数据库查询助手

### 2.1 总目标

让业务人员通过自然语言安全查询数据库。

### 2.2 核心用户

- 老板
- 运营
- 产品经理
- 数据分析薄弱的小团队
- 内部后台系统使用者

### 2.3 典型问题

- 上个月销售额是多少？
- 哪个商品退款率最高？
- 本周新增用户有多少？
- 不同渠道订单转化率如何？
- 客单价最高的用户群体是什么？

### 2.4 核心能力

- schema 读取和描述
- 自然语言转 SQL
- SQL 只读校验
- 查询确认
- 查询执行
- 结果脱敏
- 结果解释
- 查询审计

### 2.5 技术要点

- Spring Boot
- Spring AI ChatClient
- JDBC / JPA
- SQL parser 或规则校验
- prompt 模板
- audit log

### 2.6 风险

- SQL 幻觉。
- 生成错误字段。
- 越权查表。
- 查询太慢。
- 敏感数据泄露。

### 2.7 防护

- schema 白名单。
- 只读 SQL。
- limit 限制。
- timeout 限制。
- 敏感字段脱敏。
- 执行前确认。

## 3. Resume Copilot：简历筛选助手

### 3.1 总目标

帮助招聘团队快速判断候选人与职位的匹配度。

### 3.2 核心用户

- HR
- 技术负责人
- 招聘团队
- 小公司创始人

### 3.3 核心能力

- JD 解析
- 简历解析
- 技能抽取
- 项目经历总结
- 匹配度评分
- 风险点总结
- 面试题生成

### 3.4 输出

- 候选人摘要
- 技能匹配矩阵
- 缺口分析
- 面试重点
- 风险提醒

### 3.5 风险

- 歧视性判断。
- 过度自动化决策。
- 简历隐私泄露。
- 模型编造经历。

### 3.6 防护

- 明确仅辅助判断，不做自动录用。
- 输出基于简历证据。
- 隐私字段脱敏。
- 给出引用片段。

## 4. Support Copilot：智能客服助手

### 4.1 总目标

帮助客服团队提升回复效率和工单处理质量。

### 4.2 核心用户

- 客服团队
- 售后团队
- SaaS 支持团队
- 小企业运营团队

### 4.3 核心能力

- FAQ 检索
- 工单分类
- 回复草稿
- 情绪识别
- 紧急程度判断
- 转人工建议
- 质检摘要

### 4.4 输出

- 推荐回复
- 分类标签
- 紧急程度
- 转人工原因
- 客服质检摘要

### 4.5 风险

- 错误承诺。
- 泄露用户隐私。
- 不合规回复。
- 情绪识别误判。

### 4.6 防护

- 高风险问题转人工。
- 回复前人工确认。
- 敏感信息脱敏。
- 回复模板约束。

## 5. Knowledge Copilot：企业知识库助手

### 5.1 总目标

基于内部文档进行问答，并提供来源引用。

### 5.2 核心能力

- 文档上传
- 文档解析
- chunking
- embedding
- retrieval
- answer with citation
- 权限过滤

### 5.3 风险

- 答案幻觉。
- 权限越界。
- 引用不准确。
- 文档解析错误。

### 5.4 防护

- 必须给来源引用。
- 无依据时回答不知道。
- 按用户权限过滤文档。
- 保留召回片段。

## 6. Report Copilot：报表和周报助手

### 6.1 总目标

帮助团队从业务数据、任务和会议记录生成结构化报告。

### 6.2 核心能力

- 会议纪要摘要
- 任务提取
- 周报生成
- 数据摘要
- Markdown 导出
- Word 导出，后续考虑

### 6.3 风险

- 编造任务。
- 误解会议结论。
- 重要事项遗漏。

### 6.4 防护

- 输出引用来源。
- 重要任务要求人工确认。
- 明确区分事实和建议。
