# 模块详细规划

## 1. 模块设计原则

每个业务模块都必须满足：

- 业务场景明确。
- 输入输出清楚。
- 能独立 demo。
- 能复用平台能力。
- 有安全和审计边界。
- 有样例数据或样例文件。

模块不是功能堆叠，而是可交付的业务场景。

## 2. 第二模块选型结论

Data Copilot 之后，第二个模块优先选择：

> Knowledge Copilot：企业知识库助手

### 2.1 候选模块对比

| 模块 | 实用性 | 痛点强度 | Demo 独立性 | 实现风险 | 结论 |
|---|---|---|---|---|---|
| Resume Copilot | 中 | 中 | 高 | 中 | 场景清晰，但受招聘流程和合规边界影响较大 |
| Support Copilot | 高 | 高 | 中 | 中高 | 痛点强，但真实落地通常依赖客服系统、工单系统和知识库 |
| Knowledge Copilot | 高 | 高 | 高 | 中 | 最适合作为第二模块，痛点普遍且可独立闭环 |
| Report Copilot | 中 | 中 | 中 | 中 | 价值明确，但高质量报告依赖数据源、任务系统和会议记录 |

### 2.2 选择 Knowledge Copilot 的原因

- **覆盖面广**：几乎所有团队都有内部制度、产品文档、交付文档、运维手册、FAQ 难查的问题。
- **痛点真实**：新人上手慢、重复问答多、文档散落、知识无法沉淀，是中小团队和企业内部系统的高频问题。
- **闭环清楚**：上传文档、解析分片、检索问答、引用来源、审计记录，可以形成完整可演示链路。
- **依赖较少**：不强依赖招聘系统、客服系统、会议系统或第三方平台。
- **平台沉淀价值高**：可以沉淀文档解析、embedding、vector store、retrieval、citation、回答 guardrails 等能力。
- **与 Data Copilot 互补**：Data Copilot 面向结构化数据库，Knowledge Copilot 面向非结构化文档。

### 2.3 不优先选择其他模块的原因

- **Resume Copilot**：适合作品展示，但招聘筛选容易涉及偏见、歧视、隐私和“自动决策”风险，需要更强合规边界。
- **Support Copilot**：业务价值很高，但真正可用往往需要客服系统、工单状态、商品/订单信息和知识库联动，第二模块容易变重。
- **Report Copilot**：适合后续增强，但若没有稳定数据源和任务/会议输入，容易变成泛泛文本生成。

## 3. 第三模块选型结论

Knowledge Copilot 完成后，第三个模块优先选择：

> Support Copilot：智能客服助手

### 3.1 选择 Support Copilot 的原因

- **痛点强**：客服回复慢、口径不一致、重复问题多，是中小团队和 SaaS 团队非常常见的问题。
- **可以复用 Knowledge Copilot**：FAQ、退款政策、产品手册、故障处理流程都可以作为客服回复依据。
- **业务闭环清楚**：输入工单、分类、识别紧急程度、检索知识、生成回复草稿、人工确认、写审计。
- **可控风险**：MVP 只生成回复草稿，不自动发送，不直接承诺退款、赔偿、合同变更等高风险动作。
- **演示成本低**：可以用虚构客户、虚构工单和虚构知识库直接演示，不依赖真实客服系统。

### 3.2 MVP 边界

第三模块只做“客服工单辅助处理”，不做完整客服平台。

必须做：

- 工单文本输入。
- 工单分类。
- 情绪和紧急程度识别。
- 知识库依据检索。
- 回复草稿生成。
- 转人工建议。
- 高风险回复阻断或降级。
- 回复前人工确认。
- 回复审计日志。

暂不做：

- 不接真实客服系统。
- 不自动发送消息。
- 不做多渠道会话聚合。
- 不做客服排班。
- 不做工单 SLA 流转。
- 不做订单/退款真实操作。
- 不做长期对话记忆。

### 3.3 与 Knowledge Copilot 的关系

Support Copilot 应优先复用 Knowledge Copilot 已经沉淀的知识检索和引用能力。

**V3 已实现完成（2026-07）。** Support Copilot 模块已实现，见 `docs/support-copilot.md`。

实现时要注意边界：

- Support Copilot 可以只读使用 Knowledge Copilot 的检索能力。
- Knowledge Copilot 不能反向依赖 Support Copilot。
- 如果复用点变多，再从两个模块共同使用的代码中沉淀到平台层。
- 回复草稿必须保留引用来源，不能把无依据内容包装成确定答案。

## 4. Data Copilot：数据库查询助手

### 4.1 总目标

让业务人员通过自然语言安全查询数据库。

### 4.2 核心用户

- 老板
- 运营
- 产品经理
- 数据分析薄弱的小团队
- 内部后台系统使用者

### 4.3 典型问题

- 上个月销售额是多少？
- 哪个商品退款率最高？
- 本周新增用户有多少？
- 不同渠道订单转化率如何？
- 客单价最高的用户群体是什么？

### 4.4 核心能力

- schema 读取和描述
- 自然语言转 SQL
- SQL 只读校验
- 查询确认
- 查询执行
- 结果脱敏
- 结果解释
- 查询审计

### 4.5 技术要点

- Spring Boot
- Spring AI ChatClient
- JDBC / JPA
- SQL parser 或规则校验
- prompt 模板
- audit log

### 4.6 风险

- SQL 幻觉。
- 生成错误字段。
- 越权查表。
- 查询太慢。
- 敏感数据泄露。

### 4.7 防护

- schema 白名单。
- 只读 SQL。
- limit 限制。
- timeout 限制。
- 敏感字段脱敏。
- 执行前确认。

## 5. Knowledge Copilot：企业知识库助手

### 5.1 总目标

帮助团队基于内部文档快速获得有来源引用、可追溯、可审计的业务答案。

Knowledge Copilot 不是泛泛聊天机器人，而是面向企业内部知识检索和问答的助手。它必须基于已上传、已解析、已索引的知识内容回答；没有依据时必须明确回答不知道。

### 5.2 核心用户

- 新员工
- 客服和售后团队
- 实施交付团队
- 产品和研发团队
- 企业内部运营、行政、人事团队

### 5.3 典型问题

- 这个产品功能的开通条件是什么？
- 客户要求退款时应该走什么流程？
- 线上故障升级到 P1 的标准是什么？
- 新员工报销差旅费需要哪些材料？
- 某个接口的调用限制在哪里说明？
- 这份交付手册里对验收材料有什么要求？

### 5.4 MVP 核心能力

- 知识文档上传：支持 Markdown、TXT，后续扩展 PDF、DOCX。
- 文档元数据管理：标题、来源、业务分类、上传时间、启用状态。
- 文档解析：提取纯文本，保留标题层级和段落位置。
- 文档分片：按标题、段落和长度切分，保留 source、section、chunkIndex。
- embedding 向量化：通过 Spring AI embedding model 生成向量。
- 向量检索：按用户问题召回 topK 相关片段。
- 答案生成：只基于召回片段回答。
- 来源引用：答案必须返回引用片段和文档来源。
- 无依据拒答：召回结果不足或模型无法确认时回答不知道。
- 敏感信息处理：对手机号、邮箱、token、secret 等内容进行脱敏或阻断。
- 问答审计：记录问题、召回文档、引用片段、回答状态、模型名、耗时。

### 5.5 暂不做

- 不做复杂权限系统。
- 不做多租户。
- 不做企业级全文搜索后台。
- 不做文件协同编辑。
- 不做对话长期记忆。
- 不做自动采集企业 IM、网盘、Confluence、飞书文档。
- 不做大规模知识图谱。
- 不做流式回答，优先保证闭环。

### 5.6 输出

- 答案正文。
- 引用来源列表。
- 每条引用的文档标题、章节、片段摘要。
- 可信度提示。
- 无依据原因。
- 审计记录。

### 5.7 技术要点

- Spring AI ChatClient。
- Spring AI EmbeddingModel。
- PostgreSQL + pgvector。
- Spring JDBC。
- 文档解析和分片服务。
- prompt 模板集中管理。
- retrieval service。
- answer guardrails。
- audit log。

### 5.8 风险

- 模型根据常识编造答案。
- 引用片段和答案不一致。
- 检索召回不准。
- 文档内容过期。
- 文档中含有敏感信息。
- 未实现权限前误上传内部敏感文档。

### 5.9 防护

- Prompt 强制只基于召回片段回答。
- 回答必须携带 citation，没有 citation 不返回确定答案。
- 低相似度或召回不足时拒答。
- 答案生成后做引用完整性校验。
- 敏感字段默认脱敏，例如 phone、email、token、secret、password、id_card。
- 示例文档只使用虚构业务内容。
- 审计日志不记录完整文档原文，只记录文档 ID、chunk ID、片段摘要和状态。

## 6. Support Copilot：智能客服助手

### 6.1 总目标

帮助客服团队提升回复效率和工单处理质量。

### 6.2 核心用户

- 客服团队
- 售后团队
- SaaS 支持团队
- 小企业运营团队

### 6.3 核心能力

- 工单解析
- 知识库依据检索
- 工单分类
- 回复草稿
- 情绪识别
- 紧急程度判断
- 转人工建议
- 回复审计

### 6.4 输出

- 推荐回复草稿
- 引用依据
- 分类标签
- 情绪状态
- 紧急程度
- 转人工原因
- 回复风险提示

### 6.5 风险

- 错误承诺。
- 泄露用户隐私。
- 不合规回复。
- 情绪识别误判。
- 未经确认自动发送。

### 6.6 防护

- 高风险问题转人工。
- 回复前人工确认。
- 敏感信息脱敏。
- 回复模板约束。
- 回复草稿必须基于引用依据。
- 禁止自动发送。

## 7. Resume Copilot：简历筛选助手

### 7.1 总目标

帮助招聘团队快速判断候选人与职位的匹配度。

### 7.2 核心用户

- HR
- 技术负责人
- 招聘团队
- 小公司创始人

### 7.3 核心能力

- JD 解析
- 简历解析
- 技能抽取
- 项目经历总结
- 匹配度评分
- 风险点总结
- 面试题生成

### 7.4 输出

- 候选人摘要
- 技能匹配矩阵
- 缺口分析
- 面试重点
- 风险提醒

### 7.5 风险

- 歧视性判断。
- 过度自动化决策。
- 简历隐私泄露。
- 模型编造经历。

### 7.6 防护

- 明确仅辅助判断，不做自动录用。
- 输出基于简历证据。
- 隐私字段脱敏。
- 给出引用片段。

## 8. Report Copilot：报表和周报助手

### 8.1 总目标

帮助团队从业务数据、任务和会议记录生成结构化报告。

### 8.2 核心能力

- 会议纪要摘要
- 任务提取
- 周报生成
- 数据摘要
- Markdown 导出
- Word 导出，后续考虑

### 8.3 风险

- 编造任务。
- 误解会议结论。
- 重要事项遗漏。

### 8.4 防护

- 输出引用来源。
- 重要任务要求人工确认。
- 明确区分事实和建议。
