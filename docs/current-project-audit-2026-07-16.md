## 结论

2.3.0 已形成一个可运行、可改造、可交付的五模块企业业务样板。主流程均具备页面入口、
服务端 API、持久状态、人工控制、审计证据和下游结果；没有以空 Tab、仅接口或自动外发
冒充业务闭环。正式版仍是单组织模块化单体，不声明多租户 IAM、工作流平台、供应商认证
或生产托管能力。

## 五模块闭环

### Data Copilot

问题输入 → SQL 候选 → Schema/字段/函数/LIMIT Guardrail → 人工确认 → 只读 JDBC 二次
限制 → 脱敏结果快照 → CSV/XLSX 或一次性 Report 交接。治理模板和指标采用创建人/审批人
分离，不允许覆盖已批准版本。

### Knowledge Copilot

文档/受控来源 → 有界解析与版本化索引 → ACL 过滤的混合检索 → 强制引用或无证据拒答 →
用户反馈 → REVIEWER 质量处置 → 知识更新/重建/策略或跟进动作。引用只能指向当前可见版本。

### Support Copilot

工单创建/只读导入 → 脱敏和知识证据 → 风险分类 → 人工编辑/确认或转人工 → 记录客户
渠道结果；外部内部备注另走“准备意图 → 独立确认 → 处理中 → 完成/未知 → 证据恢复”。
确认草稿从不等价于给客户发消息。

### Report Copilot

手工/文件/外部来源/Data 交接/Support 指标 → 来源快照 → 结构化报告 Guardrail → 人工编辑和
确认 → 确定性导出。调度仅生成待复核草稿，带并发领取和失败记录，不自动发布。

### HR Copilot

岗位草稿 → 版本化标准 → 双人确认 → 用途化候选人授权 → 脱敏证据评估 → 人工复核队列 →
面试成员证据和多人意见；ATS 仅只读导入。员工服务为带引用制度问答与批准清单实例化的
入职任务，不输出分数、排名、概率、录用/淘汰结论，也不写 ATS。

## 架构与安全审核

- 五个业务模块均通过显式 AutoConfiguration 装配，不依赖宿主根包扫描。
- Prompt 集中在 `platform/ai-core`；AI 输出在进入状态动作前经过模块 Guardrail。
- 公共层只承载多个模块真实复用的 Web、认证角色、确认凭证、网络边界、AI 和审计能力。
- 高风险对象绑定操作者、对象、状态、有效期和一次性摘要凭证；条件更新处理重放和并发。
- Data 查询默认只读，并同时使用应用 Guardrail 与独立最小权限数据库账号。
- API 客户端错误使用稳定错误码和 request ID，不返回 SQL、供应商原始异常或堆栈。
- 外部连接只持久化环境变量引用，并执行 HTTPS 主机白名单、DNS/IP、重定向、超时和响应上限。
