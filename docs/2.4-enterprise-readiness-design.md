# 2.4 企业运行就绪与证据闭环设计

## 目标

2.4.0 不增加第六个 Copilot。它把 Data、Knowledge、Support、Report、HR 已经形成的
业务闭环进一步升级为可持续运营的企业样板：管理员能够看到稳定、可解释的风险检查，
进入对应业务页面整改，重新检查并保存不可变的就绪快照。

现有 /api/admin/diagnostics 主要展示配置、数量和 AI 用量，不能回答以下问题：

- 哪些状态会阻断可靠运行，哪些只是需要关注；
- 风险来自哪个业务模块，应进入哪个页面处理；
- 当前结论是否只是实时视图，还是可以用于交付复核的历史证据；
- 资料已过期、来源冲突或后台任务卡住时，系统是否真正失败关闭。

## 闭环

Admin 就绪页面 → 实时检查 API → 稳定检查编号与等级 → 跳转既有模块整改 →
重新执行检查 → 填写用途并保存不可变快照 → 历史交付证据。

就绪快照只保存稳定检查编号、状态、数量、时间窗口和整改路由，不保存 Prompt、SQL、
工单正文、简历、知识原文、密钥或供应商异常。快照在保留期内不可修改，过期后由定时
清理任务删除。

## 首批检查

| 模块 | 检查编号 | 触发条件 | 等级 | 整改入口 |
|---|---|---|---|---|
| Data | DATA_STALE_HANDOFF_CLAIMS | Report 交接领取超过租约窗口 | BLOCKER | Data / 结果交接 |
| Data | DATA_EXPIRED_RESULTS | 查询结果过期后仍超过清理宽限期 | WARNING | Data / 执行记录 |
| Knowledge | KNOWLEDGE_STALE_SYNC_RUNS | 来源同步长时间停在 RUNNING | BLOCKER | Knowledge / 资料来源 |
| Knowledge | KNOWLEDGE_FAILED_SYNC_RUNS | 观察窗口内失败同步没有后续成功同步 | WARNING | Knowledge / 资料来源 |
| Knowledge | KNOWLEDGE_BLOCKED_DOCUMENTS | 当前资料过期、冲突、索引失败或索引超时 | BLOCKER | Knowledge / 资料来源 |
| Support | SUPPORT_UNKNOWN_WRITEBACKS | 外部内部备注结果未知 | BLOCKER | Support / 人工复核 |
| Support | SUPPORT_STALE_WRITEBACKS | 回写长时间停在 PROCESSING | BLOCKER | Support / 人工复核 |
| Support | SUPPORT_BREACHED_SLA | 存在 SLA 已违约工单 | WARNING | Support / 质量与 SLA |
| Report | REPORT_STALE_SCHEDULE_CLAIMS | 定时任务领取超过租约窗口 | BLOCKER | Report / 定时草稿 |
| Report | REPORT_FAILED_RUNS | 观察窗口内失败调度没有后续成功草稿 | WARNING | Report / 定时草稿 |
| Report | REPORT_OVERDUE_REVIEWS | 草稿超过复核窗口仍未处理 | WARNING | Report / 报告记录 |
| HR | HR_OVERDUE_ASSESSMENT_REVIEWS | 评估超过复核窗口仍未处理 | WARNING | HR / 候选人评估 |
| HR | HR_OVERDUE_ONBOARDING_TASKS | 入职必办任务超过复核窗口 | WARNING | HR / 员工入职 |

任一 BLOCKER 使总体状态为 BLOCKED；没有阻断项但存在 WARNING 时为 ATTENTION；
全部通过时为 READY。业务积压不会被伪装成系统故障，但不确定外部结果、卡住的领取态
以及不可安全检索的知识资料必须失败关闭。

Knowledge 和 Report 的失败观察项只统计尚未被同一来源/调度的后续成功运行恢复的失败，
因此管理员完成重试后可以立即复查闭环，不需要等待观察窗口自然结束。Knowledge 来源页
同时展示冲突、失败、删除、过期和索引失败/超时项；问题卡片经人工确认后从空游标开始全量同步，
恢复内容未变的过期资料和索引失败任务。卡死的 `PROCESSING` 索引任务只能在超过租约窗口后条件取消并建立
替换任务。向量只能在锁定同一个仍为 `PROCESSING` 的租约后，与任务/文档状态在同一事务中持久化；
旧工作线程的迟到结果不能删除或覆盖替换任务的向量和状态。管理员在 HR 评估页可以直接处理同一条逾期复核队列。

探针必须一次返回上述 13 个稳定编号且数量均为非负值；缺少、增加未知编号或返回非法数量时，
整次评测失败，不得把缺失项按 0 处理成 `READY`。

## Knowledge 生命周期修正

2.4 的检索路径同时要求：

- 文档已启用、为当前版本且索引完成；
- expires_at 为空或晚于当前时间；
- conflict_status 为 NONE；
- ACL/角色可见性继续通过。

文本、关键词和向量三条检索路径使用相同条件。来源同步成功且内容未变化时也会续期文档，
避免健康的定期同步资料在 30 天后被误判为过期；同步失败则不续期，最终自然退出检索。
`business-copilot.knowledge.index-stale-after` 与就绪检查的卡住窗口默认同为 15 分钟，应在部署中保持一致。

## 数据与配置

- Flyway V32 新增 enterprise_readiness_snapshots。
- 默认快照有效期 24 小时、保留 90 天，过期查询结果清理宽限为 1 小时。
- 默认卡住任务窗口 15 分钟、人工复核窗口 24 小时、失败观察窗口 7 天。
- 所有阈值可通过 business-copilot.enterprise-readiness.* 配置。

## 管理接口

- `GET /api/admin/readiness`：使用同一时间边界重新执行 13 项实时检查。
- `POST /api/admin/readiness/snapshots`：只接收 1–200 字符的用途，服务端重新检查后追加快照；
  不接受客户端上传检查结果或哈希。
- `GET /api/admin/readiness/snapshots?page=0&size=20`：倒序分页读取历史证据。

V32 通过数据库触发器拒绝 `UPDATE`，只允许新增和保留任务执行 `DELETE`。内容哈希覆盖稳定
schema 版本、应用版本、运行模式、总体状态、检查数量与有序检查列表，不把时间、操作者或用途
混入状态哈希，因此相同状态产生相同哈希，快照编号仍保持唯一。

## 权限和边界

- 实时检查、创建快照和历史记录均位于 /api/admin/**，只允许 ADMIN。
- 整改仍在五个既有模块完成，不在 Admin 页面新增绕过业务权限的写接口。
- 不自动修复、不自动确认、不自动外发，也不把供应商 Mock 契约当成真实租户验收。
- 不建设通用工作流平台、监控平台、多租户 IAM 或第六个业务模块。

## 发布门禁

- Knowledge 三条检索路径的过期/冲突失败关闭测试。
- 就绪检查分级、哈希稳定性、快照不可变性、分页和保留测试。
- PostgreSQL V1→V32、V28→V32、V31→V32 迁移。
- Admin 桌面/移动端就绪闭环 E2E。
- 既有前端、五模块固定评测、Maven/SBOM、MySQL 和 Docker 门禁继续通过。
