# ADR-0002：基础认证角色与审计操作者上下文

- 状态：已采纳
- 日期：2026-07-15

## 背景

五个 Copilot 已包含 SQL 执行、草稿确认、报告确认和招聘材料复核等人工动作。匿名接口和只有业务 requestId 的日志无法回答“谁在什么 HTTP 请求中执行了动作”。v1.1 需要一个小而明确的单组织安全基线，但不提前实现企业身份平台。

## 决策

1. 应用默认启用表单登录和 CSRF，演示用户由环境变量配置并使用委托密码编码器存入内存。
2. `ADMIN` 可执行全部动作；`OPERATOR` 执行标准创建/分析流程；`REVIEWER` 查看审计，并只进入明确列出的确认或复核端点。
3. 未登录 API 请求返回结构化 401，越权请求返回结构化 403；静态资源、登录页和基础健康端点可匿名访问。
4. 每个 HTTP 请求生成或接收 `X-Request-Id`，认证用户名作为 actorId。过滤器在认证过滤器之后写入线程上下文，并在请求结束时清理。
5. 模块审计保留业务 requestId，同时增加 httpRequestId 和 actorId；不把密码、token、Prompt 或敏感正文写入审计。

## 后果

- 业务动作可以关联到请求和操作者，角色边界能够通过 MockMvc 回归。
- 默认演示密码只适合本机启动，共享环境必须覆盖；生产接入 OIDC/LDAP 时保留现有角色和审计上下文契约。
- 当前不实现用户管理、多租户、细粒度数据权限或外部 IdP。

## 验证

- MockMvc 覆盖匿名 401、角色 403、CSRF 和确认端点授权。
- PostgreSQL 集成测试确认审计记录持久化 httpRequestId 与 actorId。
- Compose 冒烟覆盖健康检查、CSRF 登录和认证工作台。
