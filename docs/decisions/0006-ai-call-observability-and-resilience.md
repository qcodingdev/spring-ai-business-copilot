# ADR-0006：AI 调用链、低基数指标与故障隔离

- 状态：已采纳
- 日期：2026-07-22

## 背景

五个 Copilot 已共享 AI Core，但过去只能从各模块日志分别定位模型故障，缺少统一的子调用编号、稳定操作名和可告警指标。提供方变慢或持续失败时，各业务请求还可能同时占用应用线程。

## 决策

1. 所有 Chat 和 Embedding 调用必须经过 `AiCallCoordinator`，调用链固定为“HTTP 请求上下文 → 业务服务 → AI 服务 → 调用协调器 → Spring AI → 提供方”。
2. 协调器生成 `aiCallId`，并将代码内固定的 `aiOperation` 写入 MDC；问题、Prompt、文件名和用户标识不得成为指标标签或操作名。
3. Micrometer 只记录调用类型、固定操作、provider、model、状态、耗时和提供方返回的 token 用量。
4. Chat 与 Embedding 共用有界并发许可，但使用独立熔断器，防止一个调用类型的持续故障直接阻断另一个类型。
5. HTTP 超时和受限瞬时重试使用 Spring AI 配置；并发等待和熔断由 AI Core 负责，业务 guardrail 与状态机不因降级而绕过。
6. 协调器记录中文链路摘要，Chat/Embedding 封装层只在最终转换异常时记录一次完整堆栈，避免重复刷屏。
7. Actuator 指标端点只允许 Admin/Reviewer；Prometheus 等 exporter 由具体部署按监控边界选择，不在核心应用中强制绑定。

## 后果

- 五个模块需要为每种模型调用提供稳定操作名。
- 调用繁忙、熔断开启和模型失败都返回不泄露 provider 原文的中文业务错误。
- 并发与熔断阈值可以通过环境变量覆盖，但修改后必须重新执行容量和五模块真实模型 smoke。
- 本决策不引入工作流平台、通用观测平台或新的业务模块。

## 验证

- 单元测试覆盖 MDC 恢复、成功指标和熔断开启。
- 安全测试覆盖 Reviewer 可读、Operator 和匿名用户不可读指标端点。
- 固定评测、全量 Maven、容量基线和真实模型 smoke 按运行手册执行。
